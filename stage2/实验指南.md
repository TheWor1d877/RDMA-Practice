# stage2 实验指南

模块做的事：把 stage1 的 RDMA 资源管理和单边 Write 封装成五个 C 函数，Go 经 cgo 调用。实验分两段：先在 Soft-RoCE 本机冒烟，冒烟通过后上云（vRoCE 或 eRDMA）做功能与稳定性验证。全部输出落盘 `results/`，数据回本地再分析。

## 目录与接口

```
stage2/
├── tc_rdma.h / tc_rdma.c      C 模块，编译成 libtc_rdma.a
├── go/
│   ├── tcgo.go                cgo 封装，Go 侧只持句柄
│   ├── control.go             控制面：TCP 上交换一行 JSON
│   └── cmd/
│       ├── tcserver/          接收端：预注册槽位，等校验
│       └── tcclient/          发送端：循环 Write + Poll
├── scripts/                   run_smoke.sh / run_server.sh / run_client.sh
└── results/                   所有日志与结果汇总
```

C 侧接口分三类。数据面五函数与 docs/3 签名一致：

```c
void*    tc_rdma_init(const char* dev_name);
uint64_t tc_rdma_register(void* ctx, size_t size);
int      tc_rdma_write(void* ctx, uint64_t local_handle,
                       uint64_t remote_addr, uint32_t remote_rkey,
                       size_t offset, size_t len);
int      tc_rdma_poll(void* ctx, int timeout_ms);
void     tc_rdma_shutdown(void* ctx);
```

建链辅助两个：`tc_rdma_get_endpoint` 取本端 (qpn, psn, gid)，`tc_rdma_connect` 吃对端这三项完成 INIT→RTR→RTS。QP 建链信息的交换属控制面，docs/4 划在模块职责之外，Go 侧经 TCP JSON 完成。

buffer 辅助三个：`tc_rdma_query_buffer` 查 (addr, rkey, size) 给控制面发；`tc_rdma_write_mem` / `tc_rdma_read_mem` 填数据、验数据。注册内存由 C 侧 malloc 并 reg_mr，Go 拿不到裸指针，GC 移动内存导致 MR 失效的路径被掐断。

SEND/RECV 辅助三个：`tc_rdma_send` / `tc_rdma_post_recv` 是双边操作的扩展点，`tc_rdma_get_last_wc` 返回最近一次 poll 的 CQE 详情（opcode 区分 SEND/WRITE/RECV）。五函数是 docs/3 定死的数据面契约，SEND/RECV 在这之外，标注为扩展点。

Go 侧用法见 `go/tcgo.go` 顶部注释与 `cmd/` 两个程序的 main 函数。

## Soft-RoCE 冒烟（本机）

前置三件事：`rdma link show` 看到 `rxe0 state ACTIVE`；笔记本无线网卡执行 `sudo ip neigh replace fe80::de90:9ff:fe63:5e2 lladdr dc:90:09:63:05:e2 dev wlp4s0`（原因见 stage1 使用说明第一节）；Go 在 `/usr/local/go/bin/go`。

一条命令跑冒烟，参数是每轮迭代次数：

```bash
./scripts/run_smoke.sh 50
```

脚本依次跑三轮，每轮起一次 server（预注册 8 个槽位，槽位 256KB——本机 memlock 上限 8MB，8 个 1MB 会让 `ibv_reg_mr` 失败）、跑一次 client、server 逐槽校验：

```
write  -depth 8   批量 outstanding：8 条 post 攒一批，再批量 poll
send              纯 SEND/RECV：对端挂 recv WR，按序逐条校验
mixed             一次 Write 一次 SEND 交替
```

每轮日志落 `results/smoke_<轮次>_{server,client}.log`，六条 `RESULT` JSON 行汇总到 `results/smoke_summary.txt`。通过判据对应 docs/3 的四条：

| docs/3 冒烟判据 | 看哪里 |
|---|---|
| Write 到预注册槽位，内容校验通过 | 每轮 server 日志 `mismatch_slots: 0`，逐槽位一行 `校验通过` |
| CQ 轮询收到完成 | client 每次操作后 `Poll` 成功；send/mixed 轮 server 另有 `recv_ok` 计数 |
| 重复操作不泄漏资源 | `-n` 从 50 加到 1000 再跑一遍，两端无 reg_mr/alloc 类报错，退出码 0 |
| shutdown 后资源释放干净 | 两端日志各有 `[tc] shutdown ok: 释放 ... 个槽位` |

RESULT 行字段：client 的 `writes`/`sends` 是两种 opcode 的成功次数，`fail` 非 0 时 `err` 带失败原因；server 的 `recv_ok` 是收到的 SEND 条数，`mismatch_slots` 是内容不一致的槽位数。冒烟不过不上云。

## 云上准备

选云按 docs/3 的建议：华为云有券走 vRoCE（购买 ECS 时扩展网卡勾选"启用 EFI"），阿里云有资源走 eRDMA（购买支持 eRDMA 的实例规格并为主网卡开启 ERI）。两边都不额外收费，Verbs 接口同一套。不租 H2。

要两台同 VPC 的实例：华为云明确不支持同节点 vRoCE 互通。实例规格选 CPU 通用型，操作系统选 Ubuntu 22.04，两台在同一安全组、内网互通。

系统装好后逐台执行：

```bash
# 1. 驱动。华为云按官方文档装指定版本 OFED + vRoCE 驱动；阿里云装 eRDMA 驱动
#    （具体版本号以购买页文档为准，装错版本是常见坑，现象记进错误总结）
# 2. 确认设备
ibv_devices            # 能看到 RDMA 设备
rdma link show         # 设备 ACTIVE
# 3. 锁定内存上限（冒烟 256KB 不需要，云上跑 1MB 槽位建议调大）
sudo sh -c 'echo "* soft memlock unlimited" >> /etc/security/limits.conf'
sudo sh -c 'echo "* hard memlock unlimited" >> /etc/security/limits.conf'
# 4. 编译环境
sudo apt install -y build-essential libibverbs-dev
# Go：下载 tarball 解压到 /usr/local/go
# 5. 工具链自检：两台各起一个 rping
rping -s -a 0.0.0.0 -v -C 10        # 实例 A
rping -c -a <A 的内网 IP> -v -C 10   # 实例 B
```

rping 双向各跑一轮，输出落盘：

```bash
# 实例 A
rping -s -a 0.0.0.0 -v -C 10 2>&1 | tee results/rping_server.log
# 实例 B
rping -c -a <A 的内网 IP> -v -C 10 2>&1 | tee results/rping_client.log
```

rping 不通时不往下走。安全组是否放行、ERI/EFI 是否真的开启、驱动版本对不对，逐项排查，现象记进错误总结。

## 云上运行

两台实例都把 `stage2/` 整个目录传上去（git、scp 均可）。server 每轮接受一个 client、校验完退出，所以每轮都是"A 先起 server，B 再跑 client"，共四轮：

| 轮次 | 实例 A（服务端） | 实例 B（客户端） | 验证什么 |
|---|---|---|---|
| 1 功能主路径 | `./scripts/run_server.sh -slotsize 1048576` | `./scripts/run_client.sh <A内网IP> -n 1000` | 单边 Write 连续 1000 次，docs/3 必做 |
| 2 批量 outstanding | 同上 | `./scripts/run_client.sh <A内网IP> -n 1000 -depth 16` | 16 条 WR 攒批 post 再批量 poll，SQ 深度与批处理 |
| 3 SEND/RECV | 同上 | `./scripts/run_client.sh <A内网IP> -n 1000 -mode send` | 双边操作连续 1000 次，recv WR 按序消耗 |
| 4 混合 + 链路异常 | 同上 | `./scripts/run_client.sh <A内网IP> -n 100000 -mode mixed` | 两种 opcode 混跑；跑到中途执行下面的断链步骤 |

前四轮的功能判据：client `RESULT` 行 `fail: 0`，write 轮 `writes: 1000`，send 轮 `sends: 1000`；server `RESULT` 行 `mismatch_slots: 0`，send/mixed 轮 `recv_ok` 与 client 的 `sends` 相等。第 4 轮 client 会在断链后停在错误现场。

日志自动落到各自的 `results/server_*.log` 与 `results/client_*.log`。

链路异常实验：第 4 轮 client 用 `-n 100000` 长跑，跑到中途在实例 A 上执行 `sudo ip link set <RDMA 网卡名> down`（或删掉安全组放行规则）。client 的 CQ 在 retry 耗尽后返回错误 CQE，模块打出 status（预期 `transport retry counter exceeded`），client 停止并在 `RESULT` 行记下 fail 与 err；mixed 模式下 WRITE 和 SEND 两种 WR 都会被 flush 成错误完成，两类 status 都记。server 侧断链表现为控制面 done 行读不到。实验完恢复网卡：`sudo ip link set <网卡名> up`。

## 收尾

确认以下文件都已存在于两台实例的 `results/` 后再释放实例：

```
rping_server.log / rping_client.log    # 双向自检
server_<时间戳>.log                    # -n 1000 那一轮
client_<时间戳>.log                    # -n 1000 那一轮
链路异常那轮的 client_<时间戳>.log
```

回本地拉取：

```bash
scp <user>@<A 内网 IP 或公网 IP>:~/stage2/results/*.log ./stage2/results/cloud/
scp <user>@<B 内网 IP 或公网 IP>:~/stage2/results/*.log ./stage2/results/cloud/
```

文件齐了立即释放两台实例，按小时计费。

## 数据分析（本地）

`RESULT` 行是 JSON，逐条提出来看：

```bash
grep -h RESULT stage2/results/cloud/*.log
```

异常实验的报错原文在 client 日志里搜 `CQE 错误`。对账三件事：client 的 ok 加 fail 应等于写入到失败那一次为止的次数；server 校验的槽位数应等于 client 的 ok；fail 为 0 时 `mismatch_slots` 应为 0。对不上时按日志里的进度行定位到第几次写入。

错误总结按 docs/3 要求的格式写，每条三段：现象（报错原文与发生环节）、根因、解法。现有素材四条：RTR 返回 EINVAL（`is_global` 漏设）、RTR 返回 ETIMEDOUT（IPv6 隐私扩展与 GID 失配）、rping 写 127.0.0.1 报 `No such device`（rdma_cm 按路由表映射设备）、本机 reg_mr 失败（memlock 8MB 上限）。云上新增的坑（驱动版本、ERI/EFI、安全组、错误 CQE status）跑完补进去。
