# stage1 使用说明（大白话版）

这份说明告诉你：怎么把 stage1 下的代码跑起来，跑起来之后怎么确认 docs/2 要求的每件事都发生了。整个流程就三步：配好环境 → 编译 → 开两个终端跑。

## 一、环境确认（一次性）

Soft-RoCE 设备叫 `rxe0`，先确认它存在并且是 ACTIVE：

```bash
rdma link show
```

看到 `rxe0/1 state ACTIVE` 就行。没有的话按 docs/2 的环境配置一节重新创建。

笔记本无线网卡要多做一步。wifi 开了 IPv6 隐私扩展，系统实际用的 link-local 地址是随机生成的，而 rxe 的 GID 是按 MAC 推导的，两个地址对不上，QP 迁移会卡死在超时。解法是给系统登记一条静态映射，告诉它"这个推导出来的地址就是你自己的 MAC"：

```bash
sudo ip neigh replace fe80::de90:9ff:fe63:5e2 lladdr dc:90:09:63:05:e2 dev wlp4s0
```

这条命令重启后失效，每次重启后要重新敲。地址怎么来的：你的 MAC 是 `dc:90:09:63:05:e2`，rxe 按 EUI-64 规则推导出 `fe80::de90:9ff:fe63:5e2` 当 GID，这条映射就是补上"系统里没人认领这个地址"的窟窿。换了网络环境（MAC 不变）一般不用改；如果你换了网卡，两个地址都要跟着换。

再跑一次 docs/2 要求的 rping，确认环境本身是通的：

```bash
# 终端 1（服务端）
rping -s -a 0.0.0.0 -v -C 10
# 终端 2（客户端），地址写 wlp4s0 的 IPv4，用 ip -4 addr show dev wlp4s0 查
rping -c -a 192.168.51.191 -v -C 10
```

两边都打印完 10 轮 ping data 不报错，环境就算过关。rping 通了说明建链和基本 verbs 路径没问题，后面自己代码出错就不会冤枉环境。

注意客户端地址不能写 `127.0.0.1`：rping 的 rdma_cm 按路由表把目标 IP 映射到 RDMA 设备，`127.0.0.1` 属于 `lo` 网卡，`rxe0` 绑在 `wlp4s0` 上，映射不到会报 `rdma_resolve_route: No such device`。stage1 的 demo 里 `127.0.0.1` 只是 TCP 控制面的地址，走内核网络栈，不经过这层映射，所以不受影响。

## 二、编译

```bash
cd stage1
make
```

生成两个可执行文件：`receiver`（接收端）和 `sender`（发送端）。

## 三、跑通单边 Write

开两个终端。终端 1 先起接收端：

```bash
./receiver rxe0 20000
```

终端 2 再起发送端：

```bash
./sender rxe0 127.0.0.1 20000
```

程序行为用一句话说：接收端注册一块 64KB 内存，通过 TCP 把自己的内存地址、rkey、QP 编号发给发送端；发送端拿到后把 QP 迁到就绪状态，然后直接往那块内存里写 64KB 数据——**接收端全程没有参与传输，这就是"单边"的意思**。接收端发现数据到了，逐字节校验后退出。

## 四、怎么确认 docs/2 的每件事都发生了

两份输出对照下面这张表看，全部命中就是通过：

| docs/2 要求 | 看输出里的哪一行 |
|---|---|
| PD/MR/CQ/QP 按序创建 | `[init] MR registered: ...` 和 `[init] QP created: qpn=...` |
| QP 三段迁移 INIT→RTR→RTS | `[QP] INIT ok` → `[QP] RTR ok` → `[QP] RTS ok` 三行都出现 |
| 单边 Write，接收端不 post recv | 发送端 `[send] WR 已 post`；接收端输出里没有"接收"类动作，只有等待 |
| CQ 收到完成事件 | 发送端 `[send] 收到 CQE：RDMA_WRITE 完成 status=success bytes=65536` |
| 写入内容一致 | 接收端 `[recv] 校验通过：65528 字节与发送端完全一致` |
| 资源按反序销毁 | 两边都有 `[destroy] 全部资源已按 QP->CQ->MR->buf->PD->dev 释放` |

## 五、报错了先看这两条

**`INIT->RTR 失败: errno=110`**：邻居映射丢了，重新执行第一节的 `ip neigh replace` 命令。110 是 ETIMEDOUT，意思是 rxe 拿推导的 GID 问"谁在这个地址"没人应。

**`INIT->RTR 失败: errno=22`**：EINVAL，参数不合法但不说哪个。stage1 代码里这个坑已经修了（`rdma_common.c` 的 `qp_to_rtr` 函数，`is_global` 必须置 1）；如果你改代码改出新 errno=22，优先检查 `qp_to_rtr` 里的地址向量字段。

其他错误：`没有可用的 RDMA 设备` 是 `rxe0` 不存在，回环境配置；`bind: Address already in use` 是上一次的 receiver 还没退干净，等几秒或换端口号。
