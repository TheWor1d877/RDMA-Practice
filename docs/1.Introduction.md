这个项目被分成了三个部分：

1. **系统性学 RDMA Verbs 机制**：配合知乎文章，用 Soft-RoCE 在一台机器上把 PD、MR、QP、CQ 的创建销毁、QP 三段迁移、单边 Write、完成通知全部手敲一遍。目标是看到一段 Verbs 代码知道它在干什么，出错了知道看哪里。这一章不产出模块，不设验收，自己学明白为准。
2. **写一个可复用的传输模块，并在云上验证**：产出一个包含 `init`、`register_buffer`、`write`、`poll_completion`、`shutdown` 五个函数的 C 模块，Go 通过 cgo 调用。先在 Soft-RoCE 上冒烟跑通，再原样搬到真实 RoCE 实例上做功能验证和稳定性验证。这一章是本次实验的交付物。
3. **说清楚这个模块和 TrainCache 怎么衔接**：模块在 TrainCache 数据面里干什么、接口怎么对应、哪些是下一步扩展点。这一章是定位说明，不是本次实验的交付物。

硬件路径：
**Soft-RoCE 学机制 → Soft-RoCE 冒烟模块 → 真实 RoCE 验模块**。
华为云 vRoCE 或阿里云 eRDMA 都可以，两者都“无偿启用”，不额外收费，成本主要在 ECS 实例本身。

边界路径：
1. **不碰 IB**：没有设备，准入成本太高，TrainCache 也不走 IB 梯度网络。
2. **不采信软 RDMA 性能数字**：Soft-RoCE、vRoCE、eRDMA 都不是物理网卡，性能数字没有采信价值。本实验只验证功能正确性和链路异常行为可预期。
3. **TrainCache 的 NCCL 无关性写清楚**：TrainCache 是平台侧数据缓存，RDMA 用在缓存节点到计算节点的数据搬运，不走 NCCL。NCCL 是训练框架的梯度通信层，跟平台数据流是两个平面。
4. **测完释放实例，数据先拷走**。
