## 1
RTR 返回 ETIMEDOUT：wifi 开了 IPv6 隐私扩展，接口真实 link-local 是随机地址，rxe 的 GID 却按 MAC 推导去查找，邻居解析 FAILED
解法是 ip neigh replace 加静态映射，在云上不会打开网络拓展，这个问题遇不到
命令：
```bash
sudo ip neigh replace fe80::de90:9ff:fe63:5e2 lladdr dc:90:09:63:05:e2 dev wlp4s0
```

解释：
QP 迁 RTR 时，rxe 要做地址解析，查邻居表找 fe80::de90:… 的 MAC。原来邻居表没有有效条目，rxe 触发 NDP，但全机没有接口持有 fe80::de90:…，没人应答，邻居项变 FAILED，rxe 等到超时，ibv_modify_qp 返回 ETIMEDOUT。
ip neigh replace 不是把 fe80::de90:… 配到网卡上，而是往内核的“IPv6→MAC 邻居缓存”里写死一条记录，让 rxe 在需要解析这个地址时直接命中，跳过 NDP 探测

## 2
RTR 返回 EINVAL：ah_attr.is_global 漏设。RoCE 没有 IB 的 LID，地址向量寻路只有两条途径——dlid 和 GRH 全局路由段，is_global 不置 1 的话两条都空，rxe 驱动校验不过直接 EINVAL
解法是 is_global = 1，grh.dgid 填对端 GID，grh.sgid_index 选本端 GID 表项

解释：
EINVAL 报错不指明字段，只能靠迁移前把 attr 关键字段打印出来逐个对照查。这个报错和后面的 post_recv EINVAL 是同一个教训：verbs 的 EINVAL 不告诉你原因，要么对照字段清单，要么对照 QP 状态机时序

## 3
rping 客户端报 rdma_resolve_route: No such device：客户端地址写了 127.0.0.1
解法是客户端写本机实际网卡 IP（rping -c -a 192.168.51.191）

解释：
rdma_cm 拿到目标 IP 后按路由表把 IP 映射到 RDMA 设备，127.0.0.1 属于 lo 网卡，rxe0 绑在 wlp4s0 上，映射不到就报这个错。stage2 的 TCP 控制面用 127.0.0.1 没问题，那是内核网络栈的普通 TCP，不经过 rdma_cm 的设备映射

## 4
server 预注册 8 个 1MB 槽位时 ibv_reg_mr 失败：本机 ulimit -l 只有 8MB，锁页配额装不下 8×1MB
解法是本机冒烟用 256KB 槽位（run_smoke.sh 已写死），云上放开 memlock 再跑 1MB：
```bash
sudo sh -c 'echo "* soft memlock unlimited" >> /etc/security/limits.conf'
sudo sh -c 'echo "* hard memlock unlimited" >> /etc/security/limits.conf'
```

解释：
ibv_reg_mr 要锁页并建 VA->PA 翻译表，锁页受 memlock 配额限制。报错只说 reg_mr 失败，要先查 ulimit -l 再怀疑别的

## 5
server 在 Connect 之前挂 recv WR，ibv_post_recv 返回 EINVAL，server 退出；client 随后报 transport retry counter exceeded——对端没了，所有 WR 重试耗尽
解法是 recv WR 挪到 Connect（内含 INIT→RTR→RTS）之后立刻挂，client 发第一条 SEND 前要先填 64KB payload，本端建完链立刻挂赶得早，极端撞上 RNR 由发送端 rnr_retry=3 兜底

解释：
ibv_post_recv 要求 QP 至少处于 INIT 态，RESET 态直接 EINVAL。又是一条 EINVAL，定位靠对照 QP 状态机时序：这次是状态不对，第 2 条是字段没填
