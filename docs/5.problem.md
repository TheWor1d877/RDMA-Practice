## 1
RTR 返回 ETIMEDOUT：wifi 开了 IPv6 隐私扩展，接口真实 link-local 是随机地址，rxe 的 GID 却按 MAC 推导去查找，邻居解析 FAILED
解法是 ip neigh replace 加静态映射，在云上不会打开网络拓展，这个问题遇不到
命令：
```bash
sudo ip neigh replace fe80::de90:9ff:fe63:5e2 lladdr dc:90:09:63:05:e2 dev wlp4s0
```

解释：
QP 迁 RTR 时，rxe 要做地址解析，查邻居表找 fe80::de90:… 的 MAC。原来邻居表没有有效条目，rxe 触发 NDP，但全机没有接口持有 fe80::de90:…，没人应答，邻居项变 FAILED，rxe 等到超时，ibv_modify_qp 返回 ETIMEDOUT。
ip neigh replace 不是把 fe80::de90:… 配到网卡上，而是往内核的“IPv6→MAC 邻居缓存”里写死一条记录，让 rxe 在需要解析这个地址时直接命中，跳过 NDP 探测
